# Host accessibility startup, full access and session approvals (2026-09-27)

Maintainer request: reuse the AutoJs6 unattended accessibility startup instead of asking users to enable the service by hand, offer a "full access" mode comparable to Claude Code "Bypass permissions" or Codex "Full access" with a visible but non-interrupting indicator, and offer "always allow for this session" on confirmations. Recorded as roadmap decisions D42-D44. No roadmap phase was added, split or dropped.

## Behavior

- D42 accessibility startup: before risk admission, tools whose bridge calls need accessibility (node observation/actions, screenshots, OCR, current window, system keys) call the host `accessibility.ensureEnabled`. The host (already present since the Node bridge, granted by `AiAgentGrant`) uses the Root, secure settings and Shizuku strategies the user enabled in AutoJs6, never opens the settings page and waits at most 10 s. The call shares the original tool deadline and cancellation; a late reply is fenced. A `false` reply becomes `A11Y_SERVICE_NOT_RUNNING` with a model hint, and the task card shows a shortcut to Android accessibility settings. A host `unavailable` error naming the missing accessibility capability provider (service stopped mid-run) now maps to the same code instead of `TOOL_ARGUMENTS_INVALID`. Hosts or grants without the method keep the previous flow. No host change was required.
- D43 full access: Settings "Operation permissions" chooses standard, cautious or full access (settings format v3; cautious and full access are mutually exclusive; versions 1-2 migrate to standard/cautious). Full access comes only from private settings and applies to new tasks, including script-started ones, unless the caller explicitly asks for `confirm: "cautious"`. `ConfirmationGate` then skips every confirmation, including payments, sensitive and generated scripts and memory proposals. Tool groups, budgets, host grants and argument validation are unchanged. The settings note, workbench composer, floating panel, current task card and history detail show a red text label; no dialog is shown. The private history field `fullAccess` is stripped from the host/script run projection and kept in redacted exports. Runtime guidance adds `confirmationMode` only when it is not the default, so the compact local-model prompt stays inside its 4096-token budget.
- D44 session approval: every confirmation offers "Always allow for this session" between "Allow once" and "Deny". The grant key is (tool, risk level, payment category) and lives for the current task only. A session grant for another sensitive action never covers a payment. Public step `confirmation` values remain `auto`/`allowed`/`denied`.
