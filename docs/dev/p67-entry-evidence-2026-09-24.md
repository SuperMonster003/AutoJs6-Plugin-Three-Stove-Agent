# P6.7: 悬浮球, 分享, 快捷方式与语音

本记录对应 2026-09-24 至 25 日的原 P6.7, 同时闭合原 P6.6 首项的悬浮球开关和权限申请. 不新增或拆分路线图阶段. Agent build 61, 配套宿主 build 5294 / `1fdc0db987`, 公共 JS/AIDL 契约未改变.

## 实现边界

- `FloatingBall` 由已附着的 `:agent` 运行时管理, 通过设置/预设/任务/屏幕/配置/权限事件更新, 不做空闲轮询或空闲前台服务. API 26+ 使用 `TYPE_APPLICATION_OVERLAY`, API 24/25 使用兼容窗口类型.
- 默认关闭. 设置页按需进入系统悬浮窗授权页, 返回后检查权限, 用户仍需保存设置. 旧版设置 v1 读取为关闭, 写入私有 v2 格式. 无新增模型凭据, 无障碍, 麦克风或存储权限.
- 空闲球可展开目标, 预设与语音输入; 活跃任务显示一行状态及停止按钮. 拖动位置按可用显示区域比例保存并夹紧, 展开/收起保留同一真实窗口, 以满足新 Android 对后台发起任务时可见悬浮窗的要求.
- 询问/确认复用原 `PendingCard` 和请求级可见性登记. 仅实际展开的当前插件请求抑制对应通知, 收起/隐藏后恢复通知. 沿用风险, 参数, 截止时间和逐次支付确认, 不改变授权边界. 展开卡片使用 `FLAG_SECURE`, 锁屏隐藏, 解锁后恢复紧凑球.
- 原 P6.7 文案的未附着时显示连接按钮与固定决策 D38 不一致. 本实现遵循 D38: 未附着或宿主不可用时隐藏整个球, 从工作台恢复连接. 保留原条目并在此解释, 不重新定义阶段.
- 分享仅接受 `ACTION_SEND` / `text/plain` 的有界非空文本, 去除 spans, 不转发 ClipData/任意 extras. 静态新任务快捷方式及预设页的动态/固定快捷方式均只打开草稿. 目标最多 4096 UTF-8 字节, 预设遵循现有名称校验. 外部入口不能直接执行, 回答确认或扩大权限; 已删除预设不静默回退.
- 系统 `RecognizerIntent` 跟随界面语言, 无识别器时隐藏入口. 结果仅回填, 必须手动开始. 悬浮窗通过私有 Activity/ResultReceiver 接收结果, 不自行录音.

## Redmi 12C 的实际入口与模型

- API 33, Model8 / `claude-fable-5-1`, 目标来自宿主模型目录. 在预设编辑页实际选择在线目标并保存临时 `p67-e4`, 采用审慎确认策略, 默认 40 步 / 60 调用 / 600000 ms / 300000 tokens.
- 真实走过设置开关 -> 系统显示上层权限 -> 返回勾选 -> 保存 -> 桌面显示球 -> 选择预设/输入 -> 开始. 起始 Wi-Fi 关闭, 用户提供的 LTE 为默认且已验证网络; 开启操作必须由 Agent 完成.
- 后台通知实际打开具体请求, 操作员审阅参数并单次允许打开设置. 后续请求也在真实悬浮卡片单次确认. 操作员不直接点击目标应用的 Wi-Fi 开关.
- `Connected to AutoJs6 - ...` 是只读连接状态, 模型名来自默认目标预览或最近任务, 不等同当前预设的目标. 在线模型选择在预设编辑页的模型目标中完成. 本轮实际验证 Model8 目标可列出/保存/调用.

## 真实运行与限制

E4 已通过原 P6.7 要求. 最终 Wi-Fi 单轮由真实 Model8 Fable 5.1 决策, 从桌面悬浮球开始, 后台通知中逐次确认打开设置, 进入 WLAN 及操作开关. 宿主回读 `checked`, 系统 `wifi_on` 从 0 变为 1. 操作员只回答确认, 没有替模型点击开关或运行启用 Wi-Fi 的 shell 命令. 最后从悬浮球打开历史, 进入该记录详情, 核验 Completed, 预设, 7 步预算和完成摘要.

分享经系统 SEND 入口打开草稿, 选择在线预设后手动开始, Model8 返回 OK. 快捷方式从预设页实际固定到 MIUI 桌面, 系统登记为 dynamic + pinned, 点击桌面图标带入预设和固定目标后手动开始, Model8 返回 READY. 两者为只需模型回答的独立任务, 不冒充设备操作用例.

为隔离网络因素, 后续使用 PC 回环端口 + adb reverse 的临时 CONNECT 代理, 只允许 Model8 域名的 TLS 端口, TLS 保持端到端, 不记录正文/密钥. Provider 重启后验证了实际 TCP 连接, 独立探测为 29 输入 / 1 输出 token, 4.9 s. 最终成功的 Wi-Fi/分享/快捷方式使用此路径; 路径上仍有一次 MODEL_FAILED, 不能据此宣称在线请求稳定性已解决, 也不能作为移动数据直连可靠性证据. 原 P7 保留模型失败诊断与稳定性验收.

Redmi 宿主覆盖安装及 instrumentation 重启期间, 系统一度保留 DEAD 无障碍绑定. 相关宿主真机 instrumentation 在环境就绪检查失败, 不计为通过. 临时重置服务启用列表后, Mi AI 和 AutoJs6 原有两项服务均恢复绑定, 再进行上述成功 E4. API 37 的宿主测试通过, 不掩盖真机测试准备失败.
