# P6.2 task details and history

Date: 2026-09-24. Scope: the three original P6.2 items. No roadmap item was added, split or removed. Plugin 1.0.0 / build 55; host remains build 5293. This is E0/E1/E2 evidence, using scripted models and isolated fixtures, not another real-model E4 run.

## Delivered behavior

- `RunDetailActivity` reads the complete retained journal over a private asynchronous endpoint. It shows decision summaries, tool names and parameters, confirmation outcomes, expandable observations, elapsed time and usage. The result section includes status, summary, evidence, unfinished work, errors and explicit `script.result`, including null. Structured-output fallback is labeled. Visible active tasks refresh every 500 ms; terminal records every 2 s. Leaving the screen stops its polling and binding.
- `HistoryActivity` combines status, preset and local-calendar date filters. The start date is inclusive and the end date includes the entire selected day. Filters, expanded observations and detail scroll position survive activity recreation. Dates use the host-selected locale; both pages inherit the existing host language, theme, night and layout-direction handling.
- Rerun fills the original goal and preset in the workbench. The user reviews the draft and presses Start task; it does not replay previous confirmations or start automatically. An unavailable historical preset stays selected and blocks Start until the user explicitly selects an available preset. The shared `RunLauncher` and original grants, queue, foreground service and confirmation gates still apply.
- Delete removes a terminal record after a dialog. Clear removes all terminal records, including records outside current filters, after a dialog. Active tasks are protected. Clearing a pending disk write cannot resurrect the deleted record.

## Private persistence and transport

`RunHistoryStore` uses `files/runs/<UUID>.json` and `index.json`. Each record has `{version: 1, accessedAt, run}`; the index stores versioned record identities, access times and byte sizes. Per-run files are authoritative, so a missing or damaged index can be rebuilt. Unknown versions, malformed records, invalid UUID/file-name pairs, invalid UTF-8 and structural/size violations are rejected. Unreadable storage is reported as unavailable and is not silently overwritten. Process-restarted active tasks become historical `blocked` records with `HOST_UNAVAILABLE`; they are never resumed automatically.

Retention is at most 200 records and 32 MiB, including a 32 KiB index reserve. A task still has its original 200-step / 1 MiB journal limit. Reading a detail updates its persisted last-access time; periodic refresh and journal writes do not promote old records. Cleanup evicts least recently viewed terminal records, preserving active tasks. Atomic replacements use a temporary file, backup and file sync; transient replacement files need additional working space. The store keeps only index metadata in its own cache, avoiding a second full copy of the archive in memory.

Legacy `agent-runs` files are migrated after validation. A legacy file is removed only after its versioned replacement is saved or an authoritative replacement already exists. The migration test retains all 21 fixtures; the workbench still displays only the 20 most recent tasks, sorted by start time rather than rewritten file timestamps.

`IRunHistory` and its callback are private plugin AIDL, reached by an explicit action on the existing unexported, same-UID `AgentLocalService`. Requests are bounded to 1 KiB with at most eight queued operations. IO runs on the archive's serial worker, not Binder threads. Responses larger than 32 KiB use read-only file descriptors whose temporary paths are unlinked before delivery. The public host AIDL, JSON envelope fields and 32 KiB `getRun` projection are unchanged. No host code, runtime dependency or permission was added.

## Export policy

JSON export is an explicit diagnostic allowlist. It retains the run UUID, validated state, truncation indicator, step indices, recognized tool names, confirmation outcomes, durations and usage counters. It replaces goals, preset names, decision text, arguments, observations, result summaries, evidence, unfinished details, errors and script data with redaction markers. It omits pending responses, private paths and absolute timestamps. Dynamic user-data keys are never copied. This avoids relying on regular expressions to guess addresses, phone numbers or credentials in arbitrary prose.

The export dialog explains this policy. `ACTION_CREATE_DOCUMENT` lets the user choose a destination; the plugin writes through the returned content URI without a storage permission or exported file provider. Private history remains available in the detail view. Export is not a backup or import format.
